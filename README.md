# 词间 · Lexicon

一个自用的英语词汇书房。看英文与美式 IPA，先回忆含义，再读英文解释，用间隔重复安排下一次相遇。

## 已实现

- 单词、短语、习语、句子；美式 IPA 和英文释义齐全后才进入学习队列。
- 手动编辑、批量英文、Markdown 文件/文本导入；预览、逐项修改、重复处理与受保护的补全合并。
- 使用现有 ChatGPT 等聊天订阅补全：复制提示词 → 生成 Markdown → 粘回预览，不调用付费 AI API。
- 动词五种形式、形容词/副词比较等级、带词义及前后缀关系的派生词；手动编辑、导入补全、学习答案与备份同步支持。
- 默认英→义理解卡；可选中→英、语境填空，各自拥有独立 FSRS 状态。
- 每批默认 10 个新词，学完继续下一批，每天不限批次；默认每组复习 20 次。
- FSRS 5.4.2：90% 目标保持率，1/10 分钟学习步骤、10 分钟重学步骤。
- 收藏、暂停、撤销上次评分、永久删除及统计。
- Supabase 个人账号、原子写入、幂等重试、版本冲突检测、跨设备同步。
- Markdown 内容导出、JSON 完整备份及预览恢复。
- GitHub Pages 子路径、手机与电脑布局。

音标统一使用随网站打包的 Noto Sans Regular，包含 IPA 扩展字符与希腊字母，不依赖设备安装字体或外部字体服务。字体许可证随站点发布在 `fonts/OFL-NotoSans.txt`。

## 本地运行

使用 Node.js 22.12 或更新版本：

```sh
npm ci
npm run dev
```

打开终端显示的网址。尚未配置云端时，点击 **体验示例词库** 可立即体验完整的学习、导入与备份流程。

示例模式的数据保存在当前浏览器的 localStorage，与正式账号完全分开；它不是跨设备同步，也不是正式离线学习模式。示例词库仅在首次进入时添加，不会在删除后自动补回。

## 连接 Supabase

详细步骤见 [supabase/README.md](supabase/README.md)。简要流程：

1. 新建 Supabase 项目，在 SQL Editor 按文件名升序依次执行 [migrations 目录](supabase/migrations) 中全部 SQL。已有项目只追加尚未执行的迁移，包括 [词形字段支持](supabase/migrations/202610100001_word_forms.sql)，不要重跑初始建表 SQL。
2. Authentication 设置中关闭新用户注册与匿名登录，保留 Email 登录。在 Users 中预先创建自己的邮箱密码账号。
3. 复制 `.env.example` 为 `.env.local`，填写 Project URL 与 publishable key。

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

4. 重启开发服务器，退出示例模式，使用该账号登录。另一个浏览器或手机登录同一账号即可同步。

`.env.local` 已被 Git 忽略。浏览器只使用 publishable key，绝不配置 `secret` 或 `service_role` 管理密钥。数据库访问权限由登录身份、RLS 和事务函数共同限制。

正式学习需要联网。写入成功后才进入下一题；网络中断会暂存当前评分，恢复后用原操作 ID 重试。两台设备同时回答同一卡片时，旧版本会被拒绝并刷新，不会覆盖新进度。

## Markdown 格式

每个 `##` 二级标题是一条学习内容：

```markdown
## apple
- 类型: 单词
- 美式音标: /ˈæpəl/
- 英文释义: A round fruit with red, green, or yellow skin and firm flesh.
- 中文释义: 苹果
- 例句: She ate an {{apple}} after lunch.
- 例句译文: 她午饭后吃了一个苹果。
- 标签: 日常, 食物
```

支持词性、用法、来源、笔记等字段。多行内容后续行缩进两个空格。`{{...}}` 用于标记填空答案。

词头只保留目标英文。手动保存和 Markdown 导入会移除英文 `(...)`、中文 `（...）` 成对括号及其中内容，支持嵌套；未配对的括号保留。例如 `write (wrote, written)` 导入为 `write`，词形应放进独立字段。导入预览显示清理前后的词头，并用清理后的英文匹配重复项；清理后为空则拒绝该条。JSON 备份恢复不执行词头清理。

词形模板支持以下扁平字段；重复的「派生词」每行一项：

```markdown
## write
- 类型: 单词
- 词性: 动词
- 美式音标: /raɪt/
- 英文释义: To form words on a surface or create a text.
- 动词原形: write
- 第三人称单数: writes
- 过去式: wrote
- 过去分词: written
- 现在分词: writing
- 动词说明: 不规则动词。
- 派生词: writer | 名词 | 作家；写作者 | write + 后缀 -er，去掉词尾 e
- 派生词: rewrite | 动词 | 重写 | 前缀 re-（再次）+ write

## unique
- 类型: 单词
- 词性: 形容词
- 美式音标: /juːˈniːk/
- 英文释义: Being the only one of its kind.
- 原级: unique
- 比较级:
- 最高级:
- 比较等级说明: 本条“独一无二”的绝对意义通常不分级。
```

可比较的形容词/副词填写「原级」「比较级」「最高级」，如 `good / better / best`、`fast / faster / fastest`。不可分级或没有适用形式时保留空格并说明原因；词形可选，不影响已有词条进入学习。下载模板含不规则动词、形容词、副词、不可分级义项和前后缀派生的完整示例。

派生词四项依次为英文、词性、词义、前后缀关系；字段内的 `|` 写成 `\|`，反斜线写成 `\\`，多行仍缩进两个空格。每条最多 30 个派生词，只收录有依据的常用词，不将复数、时态等屈折变化误作派生词。

只有英文也可以先保存为草稿。缺少美式 IPA、英文释义或带「待确认」标记的内容不会进入学习。完整的短语或句子应提供对应的美式音标，不通过拼接单词音标生成。

音标约定采用 Cambridge US 风格的常见美式词典宽式：`r`（不用 `ɹ`），重音置于音节起始，保留美式卷舌 `ɚ / ɝː`；按具体读音使用 `iː / uː / ɑː / ɔː`，DRESS 元音写作 `e`。下载模板及 ChatGPT 补全提示词使用同一约定。提示词要求根据词义、词性和语境确定完整表达的读音；不能确认时写「待确认」，同时保护已有有效字段和个人笔记。

Markdown 预览与手动新增/编辑保存时，只自动将 `ɹ` 整理为 `r` 并移除零宽字符、BOM、软连字符和方向控制等隐藏字符；导入预览会提示此类整理。`ᵻ / ɐ / ɾ` 会提示按具体单词核对，不机械替换；也不自动修改 `ɜ`、重音或元音长度。自动整理不等于读音校验，不影响其他字段或学习状态；JSON 备份恢复保留原始内容，不应用这套输入整理规则。

软件导出会加入稳定 ID。补全时保留 ID 可更新原词条；默认只补空白，覆盖已有内容需要在预览中明确选择。没有 ID 的同名内容需要选择合并、作为新义项或跳过。修改内容不会重置调度进度。

词形也按单个字段补空白，同一个派生词按英文与词性匹配后补充缺失内容。选择覆盖只替换导入的非空值；导入旧模板不会删除已有词形。需要删除词形时在词库编辑器中清空对应栏目。补全列表默认显示草稿，以及按词性判断缺少词形的动词、动词短语和形容词/副词；切换「全部词条」可为已经完整的词条添加派生词或核对材料。纯名词、专名和未知词性不会被自动判为缺少变形。

## 学习操作

- **显示答案**：按钮或空格键。题面显示英文和美式 IPA，释义默认隐藏。
- **评分**：`1` 忘了、`2` 费力想起、`3` 记得、`4` 很轻松。只有揭晓后才能评分。
- **完成一批**：本批每条首次评分后即可继续下一批，不必等待短期重学时间。
- **暂停**：保留数据与进度，可恢复学习。
- **永久删除**：删除该条目、卡片和历史，无法在应用内撤销，也不会再复习。主动重新导入旧内容或恢复旧备份会重新添加其中条目。
- **设置**：可调整每批数量、学习时区、中文折叠、可选题型和目标保持率。

同条目不同题型默认错开到下一学习日。一次复习中的短期重学按时出现。统计按账号设置的时区计算，不因换设备而改变日期。

## 备份

- Markdown 适合编辑与内容迁移，不含复习进度。
- JSON 包含条目、卡片、历史、批次和设置，并验证版本及数据引用。
- 恢复会完整替换当前数据，先展示数量变化并下载恢复前备份。
- 浏览器下载设置可能阻止自动下载，请确认恢复前备份已保存。

## 发布到 GitHub Pages

1. 将仓库推送到自己的 GitHub 仓库，默认分支为 `main`。
2. Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。
3. Settings → Secrets and variables → Actions → **Variables** 添加：
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
4. 推送或手动运行 **Verify and publish Lexicon** 工作流。

工作流执行单元/数据库测试、构建并发布。路径自动适配 `/仓库名/`；个人 `用户名.github.io` 仓库使用根路径。网页采用 hash 路由，不依赖服务器重写。

首次配置 Supabase Auth 的 Site URL 为正式网站地址。当前使用邮箱密码登录，不需要 OAuth 回调；如果之后启用邮件恢复或 OAuth，需在 Redirect URLs 中明确添加站点地址。

## 实现边界

面向个人词库，云端每位用户保存一份事务性 JSONB 快照；每次同步会传输完整快照。词库和历史达到较大规模后，可迁移为分表、分页和增量同步。

当前不包含完整离线学习、站内 AI API、音频朗读或语音评分，也不包含公共注册和词库分享。
